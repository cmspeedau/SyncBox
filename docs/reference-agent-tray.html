Syncbox tray menu — reference UI

Right-click (or Windows/Linux single-click) on the tray icon opens this menu; a plain icon click opens the agent UI. Locking is instant — no password needed; only when the vault is locked does the item become Unlock vault… and open the client's password window. Click items to try it.

Enter the vault password. It is used now, to derive the keys — never written down.

Icon click ≠ right-click. Left/plain click opens the agent UI (same as Open Syncbox); right-click (macOS: any click on the menu bar item) opens this menu. ownCloud uses exactly this split.
Lock is instant, unlock is passworded. Lock vault acts straight from the tray — locking only clears the derived keys, so it needs no password. Only when the vault is locked does the item become Unlock vault…, which raises the client and shows the password window.
Password only ever in the client — the tray menu itself has no password field, and a stray tray click can never unlock the vault.
No pause item on purpose — pausing lives in Settings (with durations) and the main window, so the tray menu stays five rows.

Implementation: Tauri TrayIcon with a native Menu; items relabel as SyncState changes. Icon click → show/focus the main window; Open sync folder → open-folder command; Lock vault (unlocked) → direct lock; Unlock vault… (locked) → focus client + open the password window, where unlock derives the keys and sync starts; Settings… → Settings window; Quit → agent process exit. The password field lives only in the client's own webview — never in the native menu.
