Vaults

Spaces live here, on the server. A sync space is stored in the clear — the server can index and serve it, so Browse files opens it up: read the tree, hand out a share link to one file, and pull a deletion back from the recycle bin. A vault is encrypted end to end: its keys are made and kept on each client, and this server can never read it. Either way, the folder below is where a space's files land on every client, relative to that client's home directory.

Snapshots

A snapshot is a complete, sealed copy of everything this server holds — every space's chunks and the bookkeeping — written to the configured backup target. Taking one never touches a key, and every object is checksummed as it is written, so a snapshot is tamper-evident rather than tamper-proof. A vault's contents stay ciphertext; a sync space's files are readable to whoever holds the target. Snapshots cover the whole server, not one space.

Scheduled snapshots run on this cadence. Changing it applies to the running server only; a restart returns to SYNCBOX_BACKUP_SCHEDULE in the environment.

Password

Rotate the password you sign in with — the one sync clients use too. The server re-seals it with a fresh Argon2id hash and never keeps the password itself. Confirm it is really you by entering your current password. A deployment that takes its password from the SYNCBOX_PASSWORD environment cannot change it here — set it there and restart instead.
